# 방 관리 — 기획 상세

> Screen 5: `/schedule/[id]/setting`

---

## 1. 화면 목적

팀장이 방 설정을 수정하거나, 팀장을 위임하거나, 방을 종료/삭제할 수 있는 관리 전용 페이지.

---

## 2. 접근 제어

- `member.role === 'leader'`인 경우에만 접근 가능 (MVP 기준)
- 권한 없는 사용자가 URL 직접 접근 시 → `/schedule/[id]`로 리다이렉트

---

## 3. UI 요소 및 동작

### 3-1. 방 이름 수정

- 텍스트 입력 필드 (현재 방 이름이 초기값)
- 최대 글자수: 20자
- 즉시 저장하지 않고 [저장] 버튼 클릭 시 반영
- 유효성 검사: 공백만 입력 시 오류 ("방 이름을 입력해주세요.")

### 3-2. 팀 정원 수정

- 숫자 입력 필드 (현재 설정값이 초기값)
- 입력 범위: 현재 실제 참여자 수 이상 ~ 25 이하
  - 예: 현재 참여자 3명이면 3~25로만 수정 가능
- 유효성 검사:
  - 현재 참여자 수 미만으로 설정 시 오류 ("현재 참여자 수보다 작게 설정할 수 없어요.")
  - 25 초과 시 오류 ("인원수를 입력해주세요.")

### 3-3. 날짜/시간 범위 수정

- 날짜 선택: 달력 UI, 현재 선택된 날짜들이 초기값
- 시간 범위: 시작/종료 시각 선택, 현재 설정값이 초기값
- **범위 축소 시 경고 모달**:
  - "선택 해제된 날짜/시간의 제출 데이터가 삭제됩니다. 계속하시겠어요?"
  - [취소] / [확인] 버튼
- **범위 확장 시**: 기존 슬롯 유지, 새 슬롯은 `available: false`로 초기화. 기존 멤버의 `submitted`는 모두 `false`로 리셋 → 재제출 필요
- 날짜를 1개 미만으로 줄이거나 시간 범위가 잘못되면 오류

### 3-4. 팀장 위임

- 참여자 목록 표시 (닉네임 + 역할 뱃지)
- 현재 팀장 본인을 제외한 모든 참여자에게 [팀장으로 지정] 버튼 표시
- **팀장 위임 시**: 선택된 참여자가 새 팀장이 되고, 기존 팀장은 일반 참여자로 자동 변경
- 팀은 항상 팀장 1명을 유지 (팀장 없는 상태 불가)
- 팀장 위임은 [저장] 버튼 클릭 시 반영
- 팀장 위임 기능은 팀장만 가능

### 3-5. [방 종료] 버튼 (active 상태일 때만 표시)

- 클릭 시 확인 모달: "방을 종료하면 더 이상 일정을 입력할 수 없어요. 종료할까요?"
- [취소] / [종료] 버튼
- 종료 시:
  - 방 상태 → `closed`
  - 추가 제출/수정 불가
  - 결과는 계속 조회 가능
  - `/schedule/[id]`로 이동

### 3-6. [방 삭제] 버튼

- active/closed 모두 표시
- 클릭 시 확인 모달: "방과 모든 데이터가 즉시 삭제돼요. 되돌릴 수 없어요. 삭제할까요?"
- [취소] / [삭제] 버튼
- 삭제 시:
  - 방 및 모든 멤버/가용시간 데이터 즉시 삭제
  - 홈(`/`)으로 이동

### 3-7. 상단 네비게이션

- [← 뒤로] 버튼 클릭 시:
  - 저장하지 않은 변경 사항 없음 → `/schedule/[id]`로 바로 이동
  - 저장하지 않은 변경 사항 있음 → 이탈 확인 모달 표시
    - 메시지: "저장하지 않은 변경 사항이 있어요."
    - [계속 수정] / [나가기] 버튼
    - [나가기] 클릭 시 `/schedule/[id]`로 이동 (변경 사항 폐기)

---

## 4. 저장 방식

모든 설정 변경(방 이름, 인원수, 날짜/시간 범위, 팀장 위임)은 페이지 하단의 통합 [저장] 버튼 하나로 일괄 반영한다.

| 항목           | 저장 방식                                       |
| -------------- | ----------------------------------------------- |
| 방 이름        | [저장] 버튼 클릭 시                             |
| 예상 인원수    | [저장] 버튼 클릭 시                             |
| 날짜/시간 범위 | [저장] 버튼 클릭 시 (범위 축소 시 확인 모달 후) |
| 팀장 위임      | [저장] 버튼 클릭 시                             |
| 방 종료/삭제   | 확인 모달 후 즉시 반영 (저장 버튼과 별개)       |

---

## 5. API 호출

**PUT `/api/schedules/[id]`** — 방 설정 수정

```json
Request:
{
  "title": "수정된 방 이름",
  "dateList": ["2026-05-25", "2026-05-26"],
  "timeRangeStart": 9,
  "timeRangeEnd": 22,
  "memberCount": 6
}
Response 200: { "schedule": { ... } }
Response 403: { "error": "Forbidden" }
```

**POST `/api/schedules/[id]/close`** — 방 종료

```json
Response 200: { "schedule": { ..., "status": "closed" } }
Response 403: { "error": "Forbidden" }
```

**DELETE `/api/schedules/[id]`** — 방 삭제

```json
Response 200: { "success": true }
Response 403: { "error": "Forbidden" }
```

**PATCH `/api/schedules/[id]/members/[memberId]`** — 팀장 위임

```json
Request: { "role": "leader" }
Response 200: { "member": { ... } }
Response 403: { "error": "Forbidden" }
```

> 모든 API의 요청자 인증은 쿠키에서 읽음.
