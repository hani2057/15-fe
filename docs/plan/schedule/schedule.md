## 1. 서비스 개요

링크 하나로 여러 사람이 각자의 가능/불가능 시간을 입력하고, 모두 가능한 공통 시간대를 확인하는 웹 서비스.

**목표**

- 별도 계정 없이 링크만으로 일정 조율
- 참여자가 제출하면 결과 페이지 재조회 시 최신 공통 시간 반영

## 2. 사용자 역할

| 역할          | 부여 방법                                                                             | 권한                               |
| ------------- | ------------------------------------------------------------------------------------- | ---------------------------------- |
| 팀장 (Leader) | 방 생성 시 생성자가 자동으로 팀장이 됨. 이후 팀장이 /setting에서 위임 가능 (항상 1명) | 방 종료/삭제, 설정 수정, 팀장 위임 |
| 일반 참여자   | 링크로 접근                                                                           | 본인 일정 입력/수정                |

> MVP에서 /setting 접근 권한은 팀장만 가능. 이후 역할 추가 예정 (MVP 범위 외).

**역할 인식 방법**

- 닉네임 입력 또는 방 생성 시 UUID 발급 → 브라우저 쿠키에 저장
- `role`은 쿠키에 저장하지 않음. 페이지 진입 시 API 응답(`memberList`)에서 내려온 값을 사용
- 클라이언트는 쿠키의 `memberToken`으로 API 응답 멤버 목록에서 본인 레코드를 찾아 역할 판별:
  - `member.role === 'leader'` → 팀장
  - 그 외 → 일반 참여자
- **팀장은 항상 1명** — 위임 시 기존 팀장은 일반 참여자로 자동 변경

**쿠키 구조**

```
키:  schedule_{scheduleId}
값:  { memberToken: string, nickname: string, submitted: boolean }
```

## 3. 전체 화면 목록

| 화면                  | URL                           | 접근 권한                                |
| --------------------- | ----------------------------- | ---------------------------------------- |
| 랜딩                  | `/`                           | 누구나                                   |
| 방 생성               | `/schedule/new`               | 누구나                                   |
| 참여 + 시간 입력/수정 | `/schedule/[id]/availability` | 누구나 (정원 초과 시 안내 메시지만 표시) |
| 결과 확인             | `/schedule/[id]`              | 쿠키 있는 등록 참여자만                  |
| 방 관리               | `/schedule/[id]/setting`      | 팀장                                     |

## 4. 화면 전환 플로우

```
[랜딩] /
  └─ [새 방 만들기] ─────────────────────→ /schedule/new

[방 생성] /schedule/new
  └─ [방 만들기] ────────────────────────→ /schedule/[id]/availability

공유 링크 수신 → /schedule/[id] 진입
  쿠키 있음 (submitted 무관)  → 결과 화면 그대로 표시
  쿠키 없음                   → /schedule/[id]/availability 로 이동

/schedule/[id]/availability
  쿠키 없음 + 정원 미초과      → 닉네임 입력 화면
  쿠키 없음 + 정원 초과        → "정원이 모두 찼어요" 안내 메시지만 표시
  쿠키 있음                    → 슬롯 그리드 (기존 데이터 있으면 복원, 없으면 초기값)
  ├─ [결과 보기] (쿠키 있을 때만) ─────────→ /schedule/[id]
  └─ [일정 등록] ─────────────────────────→ /schedule/[id]

/schedule/[id]
  ├─ [일정 입력하기] / [내 일정 수정] ────→ /schedule/[id]/availability
  └─ [방 관리] (팀장만) ───────────────────→ /schedule/[id]/setting

/schedule/[id]/setting
  └─ [뒤로] ──────────────────────────────→ /schedule/[id]
```

## 5. 예외 처리

| 상황                                              | 처리                                                                      |
| ------------------------------------------------- | ------------------------------------------------------------------------- |
| 존재하지 않는 scheduleId 접근                     | 404 페이지                                                                |
| 삭제된 방 링크 접근                               | 404 페이지                                                                |
| 쿠키 없는 사용자의 `/schedule/[id]` 접근          | `/schedule/[id]/availability`로 리다이렉트                                |
| 쿠키 없음 + 정원 초과 상태의 `/availability` 접근 | "정원이 모두 찼어요" 안내 메시지만 표시                                   |
| closed 방의 `/availability` 접근                  | `/schedule/[id]`로 리다이렉트 (쿠키 있을 때) / 안내 메시지 (쿠키 없을 때) |
| closed 방의 결과 화면 (쿠키 있음)                 | '종료된 방' 뱃지 표시 후 정상 조회 가능                                   |
| 팀장이 아닌 사용자의 `/setting` 직접 접근         | `/schedule/[id]`로 리다이렉트                                             |

---

## 7. MVP 범위

### 포함

- 계정 없이 닉네임 + 쿠키(UUID)로 참여자 구분
- 방 생성 / 참여 / 시간 입력 / 결과 조회
- 팀장 권한 체계 (항상 1명, 방 생성자가 초기 팀장)
- 방 종료 / 삭제 / 설정 수정
- 설정 인원수 도달 시 자동 종료

### 제외 (MVP 이후)

- OAuth 로그인
- 1시간 미만 단위 시간 선택
- Room 유효기간 자동 만료
- 방 종료 7일 후 자동 비공개
