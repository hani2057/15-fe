# 참여 및 시간 입력/수정 — 기획 상세

> Screen: `/schedule/[scheduleId]/availability`

---

## 1. 화면 목적

참여자가 방에 닉네임으로 등록하고, 본인의 가능/불가 시간을 슬롯 그리드에서 선택하여 제출한다.
기존 제출 데이터가 있으면 복원하여 수정 제출할 수 있다 (신규 제출과 동일한 UI).

---

## 2. `/schedule/[id]/availability` — 진입 조건 분기

닉네임 입력 단계와 슬롯 그리드 단계는 **완전히 분리된 화면**으로 동작한다.
쿠키 유무에 따라 두 단계 중 하나만 표시하며, 동시에 노출되지 않는다.

| 상황                    | 표시                                                                  |
| ----------------------- | --------------------------------------------------------------------- |
| 쿠키 없음 + 정원 미초과 | 닉네임 입력 화면만 표시. 슬롯 그리드 미노출.                          |
| 쿠키 없음 + 정원 초과   | "정원이 모두 찼어요" 안내 메시지만 표시.                              |
| 쿠키 있음               | 슬롯 그리드 화면만 표시. 기존 제출 데이터 있으면 복원, 없으면 초기값. |
| 방이 closed + 쿠키 있음 | `/schedule/[id]`로 리다이렉트.                                        |
| 방이 closed + 쿠키 없음 | "종료된 방이에요" 안내 메시지만 표시.                                 |

> **정원 초과 판단**: `team.memberCount` ≤ 현재 등록된 멤버 수(`memberList.length`)

---

## 3. UI 요소 및 동작

### 3-1. 방 헤더 정보

- 방 이름(팀명) 표시
- 본인 닉네임 표시 (쿠키에서 읽은 값, 쿠키 없으면 미표시)
- 제출 현황 표시: "N명 중 M명 제출 완료" (N = `memberCount`, M = `submittedCount`)
- **링크 복사 버튼** — 클릭 시 현재 URL(`/schedule/[id]`) 클립보드 복사 + "링크가 복사됐어요" 토스트

### 3-2. 닉네임 입력 화면 (쿠키 없을 때)

쿠키가 없으면 전체 화면에 닉네임 입력 관련 UI만 표시한다. 슬롯 그리드는 노출되지 않는다.

- 방 이름 표시
- 닉네임 텍스트 입력 필드 (최대 5자)
- [참여하기] 버튼
  - 클릭 시 `POST /api/schedules/[id]/members` 호출
  - **성공**: 응답의 `member.token`을 `memberToken`으로, 닉네임을 쿠키에 저장 → 슬롯 그리드 화면으로 전환 (닉네임 입력 UI 완전히 제거)
  - **실패 (중복 닉네임)**: "이미 사용 중인 닉네임이에요." 인라인 오류 표시
  - 닉네임 입력 없이 버튼 클릭 시 "닉네임을 입력해주세요." 오류

### 3-3. 슬롯 그리드 화면 (쿠키 있을 때)

쿠키가 있으면 전체 화면에 슬롯 그리드 관련 UI만 표시한다. 닉네임 입력 섹션은 노출되지 않는다.

가능/불가 시간을 선택하는 2D 그리드.

**구조**

```
        5/25(월)  5/26(화)  5/27(수)
   08 ┼─────────┼─────────┼─────────┤
      │  (셀)   │  (셀)   │  (셀)   │
   09 ┼─────────┼─────────┼─────────┤
      │  (셀)   │  (셀)   │  (셀)   │
   10 ┼─────────┼─────────┼─────────┤
      ...
```

- 열(column) 헤더: `m/d(ddd)` 형식 (예: `5/25(월)`)
- 행(row): `timeRangeStart`~`timeRangeEnd` 사이 1시간 단위
- 시간 레이블: 그리드 **왼쪽**, 행과 행의 경계에 `hh` 형식으로 표기 (예: `08`, `09`)
- 셀 내부: 레이블 없이 색깔(가능=초록, 불가=회색)만 표시

**가능/불가 입력 모드 토글 (헤더)**

그리드 헤더 영역에 "가능 | 불가" 토글을 제공한다.

| 모드          | 기본 셀 상태    | 클릭 동작              |
| ------------- | --------------- | ---------------------- |
| 가능 (기본값) | 전체 불가(회색) | 클릭한 셀 → 가능(초록) |
| 불가          | 전체 가능(초록) | 클릭한 셀 → 불가(회색) |

- **모드 전환 시 셀 상태 일괄 반전**: 가능(초록) ↔ 불가(회색) 전체 뒤집기
  - 예: "가능 모드"에서 14~16시를 초록으로 선택한 뒤 "불가 모드"로 전환 → 14~16시가 회색으로, 나머지 전체가 초록으로 변경
- 모드 전환은 입력 편의를 위한 UI 조작이며, 서버 전송 데이터(`slotList`)는 항상 각 셀의 `available: boolean` 값으로 동일하게 전달됨

**동작 (공통)**

- 셀 클릭 → 현재 모드에 따라 가능/불가 전환
- 슬롯 그리드는 쿠키가 있을 때만 렌더링됨 (비활성화 상태 없음)

**초기값 로딩**

- 진입 시 `GET /api/schedules/[id]/availability` 호출
  - 기존 제출 데이터 있으면: 슬롯 상태 복원, 입력 모드는 "가능"으로 고정
  - 기존 제출 데이터 없으면: "가능 모드" + 전체 불가(회색)로 초기화

### 3-4. 하단 액션 버튼

- [결과 보기] — **쿠키 있는 경우에만 노출**. `/schedule/[id]`로 이동 (제출 없이)
- [일정 등록] — 아래 참고

**[일정 등록] 버튼 동작**

1. 슬롯 상태를 `PUT /api/schedules/[id]/availability`로 전송
   - 서버(백엔드): DB의 `Member.submitted` → `true`로 변경
2. API 성공 응답 후 클라이언트(프론트엔드): 쿠키의 `submitted` → `true`로 갱신
3. `/schedule/[id]`로 이동

**[일정 등록] 버튼 비활성화 조건**

- 닉네임 미등록 상태 (쿠키 없음 + [참여하기] 미완료)
- 가능으로 선택한 슬롯이 없을 때
- 방이 closed 상태

## 5. API 호출

**POST `/api/schedules/[id]/members`** — 닉네임 등록

```json
Request: { "nickname": "홍길동" }
Response 201: { "member": { "id": "uuid-...", "nickname": "홍길동", ... } }
Response 409: { "error": "Nickname already taken" }
```

**GET `/api/schedules/[id]/availability`** — 기존 슬롯 조회

```json
Response 200: {
  "slotList": [
    {
      "date": "2026-05-25",
      "hourList": [
        { "hour": 14, "available": true },
        { "hour": 15, "available": false }
      ]
    },
    ...
  ]
}
```

**PUT `/api/schedules/[id]/availability`** — 슬롯 제출/수정

```json
Request: {
  "slotList": [
    {
      "date": "2026-05-25",
      "hourList": [
        { "hour": 14, "available": true },
        { "hour": 15, "available": false }
      ]
    },
    ...
  ]
}
Response 200: { "availability": { ... } }
Response 409: { "error": "Schedule is closed" }
```

> 슬롯 리스트는 방의 전체 날짜(dateList)를 빠짐없이 포함하며, 각 날짜의 hourList는 timeRange 전체 슬롯을 담는다.
> 모든 API의 요청자 인증은 쿠키에서 읽음.

## 6. 정원 관련 두 단계 처리

### 단계 1: 입장 제한 (등록 정원)

- 등록된 멤버 수(`memberList.length`) ≥ `team.memberCount`이면 신규 닉네임 등록 불가
- `POST /api/schedules/[id]/members` 호출 시 서버에서 정원 초과 여부 확인
  - 정원 초과 시 `409 Room is full` 응답
- 클라이언트는 진입 시 `GET /api/schedules/[id]`로 `memberList.length`와 `memberCount`를 비교하여 정원 초과 여부 판단

### 단계 2: 자동 종료 (제출 정원)

- 슬롯 제출 완료(`PUT /availability`) 후 서버에서 조건 확인:
  - `team.memberCount` == `submittedCount`
- 조건 충족 시 방 상태를 자동으로 `closed`로 변경
- 클라이언트는 결과 화면 진입 시 방 상태가 closed임을 확인하고 '종료된 방' 뱃지 표시
