# 결과 확인 — 기획 상세

> Screen 3: `/schedule/[id]`

---

## 1. 화면 목적

등록된 참여자(쿠키 있음)만 접근 가능하며, 현재까지 제출된 공통 가능 시간을 확인할 수 있다.
참여자 목록과 제출 현황도 함께 표시한다.

---

## 2. 접근 제어

- **쿠키 없는 사용자**: 이 화면에 직접 접근 불가. `/schedule/[id]/availability`로 리다이렉트.
  - `/availability`에서 정원이 남아 있으면 닉네임 입력 후 등록 가능
  - `/availability`에서 정원 초과면 "정원이 모두 찼어요" 안내만 표시
- **쿠키 있는 참여자**: submitted 여부와 무관하게 이 화면 접근 가능

---

## 3. 데이터 로딩

- 페이지 진입 시 `GET /api/schedules/[id]/result` 호출로 최신 데이터 조회
- 쿠키의 `memberToken`을 통해 본인 여부 및 팀장 여부 판별 (클라이언트 사이드)

---

## 4. UI 요소 및 동작

### 4-1. 방 헤더

- 방 이름(팀명) 표시
- 방 상태 뱃지: closed 상태인 경우 "종료된 방" 뱃지 표시
- **링크 복사 버튼** — 클릭 시 현재 URL 클립보드 복사 + "링크가 복사됐어요" 토스트

### 4-2. 결과 목록

공통 가능 시간(모든 제출자가 가능으로 선택한 슬롯)을 날짜별로 표시.

**표시 형식**

```
5/25 (월)  14시~16시
5/25 (월)  19시~20시
5/26 (화)  10시~12시
```

- 날짜 단위 오름차순 정렬
- **연속된 슬롯은 합쳐서 표시** — 14~15시, 15~16시 연속이면 "14시~16시"
- 날짜 형식: `M/D (요일)`
- 시간 형식: `HH시~HH시`

**월별 묶어서 보기 토글**

- 토글 버튼 레이블: "월별로 묶어서 보기"
- 기본값: OFF
- 토글 ON 시: 동일한 달에 속한 결과 중 가장 첫 번째 항목 위에 `M월` 형식의 월 레이블을 연한색 텍스트로 표시
- 토글 OFF 시: 월 레이블 없이 목록만 표시
- 순수 클라이언트 표시 처리 (API 변경 없음)

```
(토글 ON 예시)
5월                    ← 연한색 텍스트
5/25 (월)  14시~16시
5/26 (화)  10시~12시
6월                    ← 연한색 텍스트
6/3 (수)   9시~11시
```

**제출자 없을 때**

- 결과 목록 비움
- 안내 문구: "아직 제출한 참여자가 없어요."

**공통 가능 시간이 없을 때** (제출자는 있으나 교집합이 0)

- 결과 목록 비움
- 안내 문구: "모두 가능한 시간이 없어요."

### 4-3. "1명만 불가 시간" 토글

- 기본 상태: 숨김
- 토글 버튼 레이블: "1명만 안 되는 시간 같이 보기"
- 토글 ON 시:
  - 공통 가능 시간 목록 아래에 `nearMissSlotList`에서 `unavailableCount: 1`인 항목을 표시
  - 색상으로 구분 — 공통 가능 시간과 시각적으로 구별되는 색 사용 (색상 토큰은 디자인 단계에서 확정)
  - 형식 동일: `M/D (요일) H시~H시`
  - 해당 슬롯이 없으면 섹션 표시 안 함

### 4-4. 참여자 현황

- 헤더: "N명 중 M명 제출 완료" (N = `memberCount`, M = `submittedCount`)
- 참여자 목록 — 닉네임 뱃지들을 나열하여 표시
  - 제출 완료: 메인 컬러 뱃지
  - 미제출: 회색 뱃지
  - 정렬 순서: 닉네임 등록 순 (입장 순)
- 팀장에게는 닉네임 뱃지 위(또는 옆)에 "팀장" 레이블 표시 — 위치는 디자인 단계에서 확정

### 4-5. 하단 액션 버튼

| 버튼            | 노출 조건                                  | 동작                                 |
| --------------- | ------------------------------------------ | ------------------------------------ |
| [일정 입력하기] | 쿠키 있음 + submitted: false + 방이 active | `/schedule/[id]/availability`로 이동 |
| [내 일정 수정]  | 쿠키 있음 + submitted: true + 방이 active  | `/schedule/[id]/availability`로 이동 |
| [설정]          | 팀장                                       | `/schedule/[id]/setting`으로 이동    |

---

## 5. 방 상태별 화면 차이

| 방 상태 | 결과 조회 | [내 일정 수정/입력] | [설정]                     |
| ------- | --------- | ------------------- | -------------------------- |
| active  | 가능      | 표시                | 표시 (팀장만)              |
| closed  | 가능      | 숨김                | 표시 (팀장만, 삭제만 가능) |

> closed 상태에서는 방 삭제만 가능. 설정 수정/종료 버튼은 /setting에서 비활성화 또는 숨김 처리.

---

## 6. API 호출

**GET `/api/schedules/[id]/result`**

```json
Response 200:
{
  "commonSlotList": [
    { "date": "2026-05-25", "hour": 14 },
    { "date": "2026-05-25", "hour": 15 }
  ],
  "nearMissSlotList": [
    {
      "unavailableCount": 1,
      "slotList": [{ "date": "2026-05-25", "hour": 16 }]
    }
  ],
  "memberList": [
    { "id": "uuid-...", "nickname": "홍길동", "role": "member", "submitted": true },
    ...
  ],
  "memberCount": 5,
  "submittedCount": 3
}
```

> `nearMissSlotList`는 현재 API에 미구현. 설계 단계에서 추가 필요. 나중에 2명 이상 불가 슬롯을 추가할 경우 `unavailableCount` 항목만 늘리면 됨.

---

## 7. 결과 목록 생성 로직 (클라이언트)

```
commonSlotList (API 응답, date/hour 오름차순 정렬됨)
  → 날짜별로 그룹핑
  → 각 날짜 내에서 연속된 hour 그룹핑
    (연속: 현재 hour == 이전 hour + 1)
  → 그룹별로 "시작시~종료시" 문자열 생성
    (종료시 = 마지막 슬롯 hour + 1)
```

예시:

```
[{date:"2026-05-25", hour:14}, {date:"2026-05-25", hour:15}, {date:"2026-05-25", hour:18}]
→ "5/25 (월) 14시~16시", "5/25 (월) 18시~19시"
```
